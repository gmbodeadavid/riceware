## 1. IDENTITÉ
================================================================================

Nom          : RiceWare CI
Slogan       : "From rice husks and straw to better tableware."
Vision       : Transformer les déchets agricoles de Côte d'Ivoire (coques et paille de riz)
               en vaisselle biodégradable premium, pour remplacer le plastique jetable.
Mission      : Produire, commercialiser et tracer des articles de table eco-responsables
               (assiettes, gobelets, couverts, barquettes) à partir de matière première
               locale, avec un back-office de production rigoureux.
Pays         : Côte d'Ivoire (CI)
Devise       : XOF / FCFA (Franc CFA ouest-africain)
Langues      : Français uniquement (fr). Champs blog multilingues (en, ko) présents mais non actifs.
Stade        : Prototype commercial avancé — e-commerce opérationnel, back-office production
               fonctionnel, paiements Mobile Money non encore intégrés côté code.
Cibles       :
  - B2C : particuliers, cantines, hôtels, événementiel (via site e-commerce)
  - B2B : grossistes, clients pilotes, partenaires institutionnels

Produits (src/lib/production/types.ts) :
  - Assiette plate (Ø 260 mm)
  - Bol
  - Gobelet
  - Barquette repas
  - Fourchette
  - Cuillère

### Découpage front/back/API

| Couche         | Pattern                          | Description                                    |
|----------------|----------------------------------|------------------------------------------------|
| Pages publiques| Server Components (async)        | SSR avec Prisma direct, pas d'API route        |
| Pages admin    | Server Components + Client Forms | requireAdminPage() guard, forms client         |
| Composants UI  | Client Components ('use client') | Formulaires, modales, sidebar, panier          |
| API routes     | Next.js Route Handlers           | REST JSON, protégées par rejectUnlessPermission|
| Auth           | JWT httpOnly cookie              | 7 jours TTL, vérification sur chaque requête   |

### Conventions de nommage
- Fichiers : kebab-case pour routes, PascalCase pour composants
- API routes : /api/{domain}/{resource}/[id]/route.ts
- Fonctions queries : list*, get*, create*, update*, delete* (CRUD explicite)
- Types : PascalCase, suffixe Row/Mapped/Input selon usage
- Permissions : domaine:action (ex: lots:write, orders:view)

### Rôles et permissions (src/lib/rbac.ts)

| Rôle        | Label                  | Permissions                                                    |
|-------------|------------------------|----------------------------------------------------------------|
| admin       | Administrateur         | TOUTES (20 permissions)                                        |
| production  | Opérateur production   | dashboard:view, lots:view, production:r/w, quality:r/w, stocks:r/w, documents:view, reports:view |
| logistics   | Resp. logistique       | dashboard:view, lots:r/w, stocks:r/w, partners:r/w, documents:r/w, reports:view |
| sales       | Commercial             | dashboard:view, orders:r/w, lots/production/quality/stocks/partners/documents:view, reports:view |
| reader      | Lecteur seul           | dashboard, orders, lots, production, quality, stocks, partners, documents, reports (view only) |

### Liste complète des permissions (20)
dashboard:view, orders:view, orders:write, lots:view, lots:write,
production:view, production:write, quality:view, quality:write,
stocks:view, stocks:write, partners:view, partners:write,
documents:view, documents:write, reports:view,
users:manage, settings:manage, content:manage, catalog:manage

### Guards
- Server-side : requireAdminPage(permission) dans src/lib/admin-guard.ts
  → redirige vers /admin/login si non authentifié
  → redirige vers /admin?refus=1 si permission insuffisante
- API-side : rejectUnlessPermission(request, permission) dans src/lib/admin-auth.ts
  → retourne 401 JSON si session invalide
  → retourne 403 JSON si permission insuffisante

### Session
- Cookie httpOnly "riceware_admin_session" contenant JWT signé
- Payload : { userId, role, permissions[], name, email, iat, exp }
- Expiration : 7 jours
- Vérification : verifyAdminToken() à chaque requête API

### Compte admin historique
- Sans email (ADMIN_PASSWORD_HASH dans .env) — hash bcrypt
- Comptes multi-rôles : email + password (table User)
- Script de création : scripts/create-admin.ts

## RÉSUMÉ EN 10 LIGNES
================================================================================

1. RiceWare CI est une startup ivoirienne qui transforme les déchets de coques de riz en vaisselle biodégradable.
2. Le projet est un monorepo Next.js 16 (App Router) + React 19 + TypeScript + Tailwind v4 + Prisma + SQLite.
3. Il comprend trois espaces distincts : site e-commerce public, blog, et back-office production.
4. Le back-office couvre l'intégralité de la chaîne opérationnelle : rizeries → lots → production → qualité → stocks → commandes.
5. L'authentification est JWT (bcrypt) avec 5 rôles granulaires (admin, production, logistics, sales, reader).
6. Les données sont 100% réelles — aucun mock — toutes les pages admin utilisent Prisma directement côté serveur.
7. La base de données SQLite contient 24 modèles couvrant e-commerce, production, qualité et blog.
8. Les paiements Mobile Money (Wave, Orange Money, etc.) ne sont pas encore intégrés côté API.
9. Il manque les modules RH, rémunérations, KPIs environnementaux/sociaux, et les emails transactionnels.
10. La migration vers PostgreSQL sera nécessaire avant une mise en production à charge élevée.
